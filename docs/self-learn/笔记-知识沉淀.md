# 知识沉淀与记忆系统学习笔记

## 概览

知识沉淀是将对话、任务结果和经验整理为可长期保存、检索、更新与复用的信息。保存完整会话提供原始材料；提炼结论、判断适用范围、处理冲突并在后续任务中使用，才形成完整的知识复用流程。

本笔记整理 DSH 已有能力、第三方记忆服务与通用用户记忆的设计方式。DSH 部分以当前仓库实现和包文档为依据，第三方入口依据本次阅读的官方资料；通用用户记忆部分是设计参考，不表示 DSH 已经实现。本文不提供未经执行验证的安装步骤。

## 一、DSH 的知识沉淀能力

DSH 具备保存会话、检索历史、读取文件化知识和接入外部记忆服务的基础组件。当前查阅范围内，没有发现默认启用的“每次任务结束后自动提炼、去重、维护并召回长期知识”的完整流程。

| 能力层 | 当前机制 | 对知识沉淀的作用 |
|---|---|---|
| 原始记录 | Session 事件记录、持久化及恢复 | 保留对话、工具调用与结果 |
| 历史复用 | 会话搜索、事件读取、跨会话引用 | 查找和使用过去的材料 |
| 文件化知识 | Markdown 笔记、AGENTS.md、SKILL.md | 将结论转为可维护的文档、规则或操作指令 |
| 外部记忆 | MCP 客户端连接记忆服务 | 使用提供方的持久存储与检索能力 |

### 会话记录与历史检索

会话日志记录发生过什么，但不会自动把全部日志变成经过筛选的知识条目。实验性的 [tool-session-query](../../packages/experimental/tool-session-query/README.zh.md) 可以让模型搜索既往会话、搜索会话内事件、追踪关系和读取具体事件；该包按需启用，跨会话访问要求目标与调用方的工作目录严格匹配。

[session-reference](../../packages/context/session-reference/README.zh.md) 支持把其他会话的有界只读快照引入当前上下文。引用内容作为不受信任的背景，不能据此继承原会话中的权限或工具执行请求。

`packages/experimental` 表示能力仍处于评估阶段、不提供产品支持承诺，并不是专门的知识库模块。正式的会话查询服务与实验性的模型调用入口应分别理解，见 [experimental 状态说明](../../packages/experimental/README.zh.md#status)。

### 文件化沉淀

用户要求 Agent 总结结论并写入文档，是一种明确的知识沉淀方式。例如本目录中的学习笔记保存了概念说明和源码入口，但普通 Markdown 不会因为位于 `docs/` 就自动进入每个新会话；后续需要读取、检索或通过适当入口引用。

[agent-instructions](../../packages/context/agent-instructions/README.zh.md) 负责加载适用的工作区指令；Skill 系统提供摘要发现和按需正文加载。它们可以消费已经整理好的规则与流程，但 Skill 加载器本身不会自动把每次对话转成新技能。

### 会话压缩与长期记忆的区别

[compaction-basic](../../packages/compaction/compaction-basic/README.zh.md) 在上下文压力增加时，把较早历史压缩为摘要并保留近期内容，帮助长会话继续执行。它处理当前会话的上下文长度，不因此自动建立独立的跨会话知识库。

## 二、不同知识应该放在哪里

先判断信息的用途，再选择载体。操作流程、稳定规则、事实和原始记录需要不同的更新与读取方式。

| 内容 | 载体 | 后续使用方式 |
|---|---|---|
| 学习总结、技术解释 | 普通 Markdown 文档 | 按需读取或检索 |
| 项目约定、固定工作规则 | AGENTS.md | 加载适用的用户或项目指令链 |
| 可重复执行的任务流程 | SKILL.md | 先发现摘要，再加载完整指令 |
| 持久的设计决策及理由 | 仓库 Agent Notes | 按项目规则查阅与维护 |
| 用户偏好、项目事实、经历 | 记忆条目或用户资料 | 按用户与任务范围检索 |
| 原始对话与工具执行过程 | Session 日志 | 恢复、审计、引用或搜索 |

Skill 主要回答“某类任务应该怎么做”，记忆主要回答“关于这个用户、项目或过去任务，已经知道什么”。例如“如何处理 PDF 表单”适合 Skill，“某个项目的 PDF 模板位置及上次处理遇到的问题”适合项目记忆。

## 三、三种第三方记忆服务

Memorix、MCP Reference Memory 和 Engram 都独立于 DSH。它们保存和检索数据，不通过保存记忆来修改大模型参数。

| 服务 | 定位 | 主要组织方式与特点 |
|---|---|---|
| [Memorix](https://github.com/AVIDS2/memorix) | 面向编程 Agent 的跨工具记忆层 | 强调在不同编程工具间复用项目记忆，提供 MCP 与直接 CLI 等入口 |
| [MCP Reference Memory](https://github.com/modelcontextprotocol/servers/tree/main/src/memory) | 基础的通用知识图谱记忆服务器 | 使用实体、关系和观察组织信息，持久化到本地 JSONL 文件 |
| [Engram](https://github.com/Gentleman-Programming/engram) | 面向编程 Agent 的持久记忆系统 | Go 实现，使用 SQLite 与 FTS5 全文搜索，提供多种调用及交互入口 |

Memorix 和 Engram 的产品定位偏向编程，重视项目与开发任务经验，但并非只能保存代码文本。MCP Reference Memory 可以直接表示用户偏好、人物关系及其他通用事实。

### 知识图谱示例

MCP Reference Memory 的实体是具有名称与类型的对象，观察是附属于实体的一条事实，关系表示实体之间的有向连接。

```text
实体：项目 A
  观察：使用 pnpm
  观察：提交前执行文档检查

实体：用户张三
  观察：偏好中文解释

关系：用户张三 → 维护 → 项目 A
```

图谱结构不等于语义搜索或自动推理。仓库参考指南描述的 MCP Reference Memory 使用子字符串搜索，不提供 embedding、自动摘要、冲突消解或遗忘策略；其他服务的检索和维护能力也应分别确认，不能因为都叫“记忆系统”就视为相同。

### 与 DSH 的关系

DSH 提供三份默认关闭的参考配置，通过 MCP 客户端连接这些服务。DSH 负责建立连接、发现并暴露工具；服务器安装、数据库初始化、模型或 embedding 配置、数据迁移等由外部系统及部署者负责。参考配置不代表项目对第三方系统的推荐或持续支持承诺。

仓库参考配置测试的版本与上游最新版本可能不同。实际部署应对照 [第三方记忆 MCP 指南](../user/guide/mcp-memory.zh.md) 及所选版本的官方文档，不能把上游新增功能直接视为仓库参考版本的能力。

## 四、是否只能通过 MCP 访问

MCP 是工具调用协议，不是记忆存储格式，也不意味着调用者必须是大模型。普通后端程序也可以实现 MCP 客户端，自行决定何时写入、检索或删除记忆。

| 服务 | MCP 以外的入口 | 使用区别 |
|---|---|---|
| Memorix | CLI、Hooks 集成、HTTP 服务与管理界面 | CLI 可以直接搜索、写入及导入导出，不依赖 MCP 会话 |
| MCP Reference Memory | 官方文档主要提供 MCP 服务入口 | 未在本次查阅的文档中发现独立的通用 REST API 或记忆增删查 CLI；启动命令主要用于运行 MCP 服务 |
| Engram | CLI、HTTP API、TUI | 普通程序可以使用 HTTP API，用户也可以通过终端操作 |

以上入口依据 [Memorix 官方说明](https://github.com/AVIDS2/memorix)、[Reference Memory 官方说明](https://github.com/modelcontextprotocol/servers/tree/main/src/memory) 和 [Engram 官方说明](https://github.com/Gentleman-Programming/engram)。

HTTP 只是传输方式之一，不必然表示通用 REST API。例如 Memorix 的 `/mcp` 端点通过 HTTP 传输 MCP 请求，调用方仍需遵循 MCP 协议。读取底层文件或数据库也不等同于受支持的应用接口。

```text
MCP 接入：应用 → MCP 客户端 → 记忆服务

普通 API 接入：应用 → HTTP API → 记忆服务

命令行接入：用户或脚本 → CLI → 记忆存储
```

DSH 的参考配置选择 MCP，是集成方式的选择，不限制第三方软件提供其他入口。

## 五、通用用户记忆的设计参考

以下是普通用户产品的设计思路，不是 DSH 已实现功能清单。用户记忆通常围绕偏好、事实、持续事项与经历组织，并明确区分一次性要求和长期信息。

### 记忆类型

| 类型 | 示例 | 更新与使用特点 |
|---|---|---|
| 用户偏好 | 默认中文、喜欢简短回答 | 稳定且适用时提供给模型 |
| 用户事实 | 居住城市、职业 | 需要来源，可能随时间变化 |
| 持续事项 | 正在备考、装修或学习某课程 | 需要维护状态与有效期 |
| 历史经历 | 上次讨论的方案及最终选择 | 根据当前任务按需召回 |
| 临时上下文 | 今天的安排、这次希望详细回答 | 不一定长期保存 |

例如“这次请详细解释”不应自动覆盖“平时喜欢简洁回答”的长期偏好。长期偏好也不应压过用户当前的明确要求。

### 提取、存储与召回流程

```text
用户对话或任务结果
  → 识别值得保留的信息
  → 判断来源、保存条件和适用范围
  → 检查重复、冲突与有效期
  → 写入用户记忆库
  → 新任务到来时检索相关条目
  → 将必要内容加入模型上下文
  → 根据新证据更新或删除
```

记忆条目可以包含用户身份、类别、内容、来源消息、作用范围、状态、创建与确认时间、过期时间和替代关系。下面是数据设计示意，不是现有服务的 API：

```json
{
  "user_id": "user-123",
  "category": "preference",
  "content": "默认使用中文回答",
  "source": "explicit_user_statement",
  "source_message_id": "message-456",
  "scope": "global",
  "status": "active",
  "expires_at": null
}
```

来源信息用于区分用户明确表达、模型推断和第三方引用，支持解释、纠正及删除。是否写入、召回哪些条目和何时更新，需要应用策略或工作流定义；接通存储服务本身不会完成这些判断。

### 存储与检索选择

| 机制 | 适合的信息 |
|---|---|
| 结构化数据库或 KV | 语言、时区、输出偏好等明确字段 |
| 全文检索 | 人名、事件名称、精确关键词 |
| 向量检索 | 表述不同但语义相关的经历与笔记 |
| 知识图谱 | 人物、组织、项目之间的关系 |

基础设计可以使用资料表保存稳定偏好、记忆条目表保存事实与经历，再按检索需求添加全文或向量索引。无需一开始就使用向量数据库，也无需把全部记忆放入每次模型请求；少量通用偏好可以直接提供，其他内容按当前任务召回。

### 冲突、时效与用户控制

用户先说住北京，后来明确说搬到上海时，系统应更新当前居住地；如果保留历史信息，需要标注时间，避免两个城市同时作为当前事实提供给模型。

- 提供记忆查看、修改、删除和暂停保存的入口。
- 使用真实用户身份授权读写，不能仅依赖提示词要求模型隔离用户。
- 区分稳定事实、临时要求和模型推断，对敏感信息设置明确保存规则，避免默认记录密码或验证码。
- 对过期、被替代或用户撤回的条目，停止作为当前有效事实召回。
- 检查写入成功、新会话召回、更新后旧值不再作为当前事实、删除后不可召回，以及不同用户间的隔离。

## 六、在 DSH 中组合这些能力

DSH 可以通过插件、文件工具、技能和 MCP 服务组合知识沉淀流程。需要先决定保存目标，再定义触发与维护规则。

| 目标 | 可使用的基础能力 | 仍需明确的策略 |
|---|---|---|
| 整理项目学习成果 | 文件写入、Markdown 文档 | 总结范围、文档位置、维护方式 |
| 复用操作经验 | Skill 发现与加载 | 何时提炼为技能、如何审核与更新 |
| 找回过去的工作 | 会话查询与引用 | 何时检索、如何筛选相关证据 |
| 跨会话保存用户信息 | MCP 记忆服务 | 用户隔离、保存条件、冲突处理与遗忘 |
| 自动任务复盘 | 事件扩展点与工作流组合 | 触发时机、提取标准、写入失败处理与质量验证 |

完整自动化还需要回答：什么信息值得记住，谁允许保存，何时触发总结，怎样避免重复，冲突由谁裁决，以及新任务如何召回。文件、日志和外部服务只是这些流程使用的存储与访问组件。

## 七、常见理解偏差

| 理解偏差 | 实际区别 |
|---|---|
| 保存会话就是自动知识沉淀 | 会话是原始材料，提炼和维护需要额外流程 |
| 压缩摘要就是跨会话长期记忆 | Compaction 首先解决当前会话的上下文长度 |
| 写入 docs 后每次会话都会知道 | 普通文档仍需要被读取、检索或引用 |
| Skill 会自动从对话学习 | Skill 系统加载已有指令，生成与维护技能需要另行组织 |
| 接上 MCP 就会自动记住所有内容 | MCP 暴露工具，保存和召回时机仍由调用方及策略决定 |
| 使用 HTTP 就是不使用 MCP | MCP 也可以通过 HTTP 传输 |
| 编程记忆系统只能保存代码 | 产品定位偏编程，不限制其只能存代码文本 |
| 所有记忆服务都有语义检索 | 子字符串、全文和向量检索是不同机制 |
