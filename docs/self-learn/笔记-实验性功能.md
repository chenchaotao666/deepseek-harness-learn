**1. “实验性”具体意味着什么**

仓库明确规定：

- 能力仍在评估中，暂不提供产品支持承诺。
- 行为和 API 可能变化，功能也可能被撤回。
- 工程、安全、测试、文档和已发布数据的维护义务仍然适用。
- 满足正式产品要求后，可以迁移到对应功能组。

所以它包含可以使用的功能，也承担验证设计和使用价值的任务。实验性状态说明 (packages/experimental/[README.zh.md](http://README.zh.md)#status)

**2. 里面有哪些功能**

当前分支的主要方向包括：


| 方向       | 示例包                                                 | 功能                 |
| -------- | --------------------------------------------------- | ------------------ |
| 历史会话检索   | `tool-session-query`、`session-search`               | 让模型搜索历史会话并读取事件     |
| 持久终端     | `tool-terminal`、`terminal-bundle`                   | 提供持续存在的终端工具        |
| 重复委派     | `tool-ralph`、`ralph-bundle`                         | 通过多轮新 agent 执行任务   |
| 浏览器与桌面操作 | `browser-use-*`、`cua`、`computer-use-*`              | 接入不同浏览器、计算机操作实现    |
| 语音输入     | `speech-to-text-*`、`client-ui-voice-input`          | 语音识别和界面录音          |
| 会话协作     | `liveshare`                                         | 分享会话，控制查看或写入能力     |
| 开发工作流    | `worktree`、`forge-*`                                | Git 工作树、PR 查询与会话关联 |
| 个性化扩展    | `creation-recommendations`、`plugin-recommendations` | 在对话中创建界面插件或推荐插件    |
| 调试与观测    | `inspector`、`session-inspector`、`client-ui-stats`   | 检查运行状态、原始日志和耗时等信息  |


**3. 它们怎样接入系统**

多数能力仍使用普通的 Cordis 插件机制：注册服务、工具、事件监听或客户端组件。一个功能可能拆成多个包，例如语音输入：

```
speech-to-text                 定义识别服务
        ↑
speech-to-text-sensevoice      提供具体识别实现
        ↑
api-speech-to-text             提供带认证的调用入口
        ↑
client-ui-voice-input          提供录音与文字插入界面

voice-input-bundle             组合上述插件

```

其中 `bundle` 负责组合和交付，不等同于单个业务实现。

**4. “实验性”“可选”“官方”是三个不同维度**


| 名称      | 描述什么              |
| ------- | ----------------- |
| **实验性** | 成熟度与支持承诺          |
| **可选**  | 是否需要用户显式启用        |
| **官方**  | 是否由项目维护并在官方插件分组展示 |


一个功能可以同时是“官方维护、默认关闭、实验性”。也不能仅凭目录就判断所有包都默认关闭，应查看它的实际组合配置。

结合前面讨论的记忆能力：`experimental/tool-session-query` 提供的是**历史信息检索工具**；它放在这里，表示这项面向模型的能力仍处于实验阶段，不代表整个 `experimental` 都是知识或记忆模块。
